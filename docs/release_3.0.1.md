# 3.0.1：并行恢复与新批次采样

2026-10-26。服务器旧批次曾出现313成功、36失败、8个Python工作进程存活但无原生引擎且日志约22小时不更新。随后确认本地`ansyscl.exe`许可共享连接异常；清理客户端后预检查和两个原生引擎重新推进。用户要求停止此批，保留旧成功数据，另开1000组新几何。

本版修改：

- 并行入口完整传递`--seed`。新目录可指定20261026；已有目录沿用原seed，显式冲突拒绝。原默认seed20261023保持。两个1000组计划各自唯一，包含物理镜像等价定义后无交集。
- 独立、仅观察的watchdog每30秒检查已核实工作进程的当前求解日志。持续600秒无引擎且无求解进度时，返回专门停滞码，PS控制器在监控异常捕获块之外明确停止继续派发。不会自动终止原工作进程或修改／重试失败样本。
- 观察间隙超过90秒、PID或样本变化、日志更新、引擎出现、观察权限不足均打断连续计时。旧中断日志不算当前求解；有新status2回执的结果导出阶段被排除。没有当前求解日志的初始化阶段仍由监控提示，不做笼统的墙钟超时杀进程。
- `recover_stalled_task.py --stop-active`用于用户主动停止当前批次。锁定控制器目录后核实任务进程身份，仅停止任务工作进程和捕获的FDTD引擎／CAD子进程，确认退出后备份中断现场；原文件不删除，成功／失败清单不改写，未提交NPZ不自动接入。服务进程、许可客户端和其他任务不处理。
- 合并导出只提交已存在清单的任务分片；未启动的后续分片保留pending，不再导致部分成功数据导出失败。显式串行merge输入校验保持严格。

新服务器任务使用独立目录`jobs/paired1000_v301_seed20261026`，8并发×7线程请求56／64逻辑CPU。旧批次不续算，不替换旧313组，所有原失败及恢复备份保留。此配置提高请求的并行容量，实际吞吐与原生许可并发尚需服务器确认。

版本不改变As₂Se₃／Au100／玻璃350、600–1400nm、七参数定义、材料表、求解器、场重建或数值门槛。新wheel沿用已验证的物理实现，本次回归采用模拟场与进程／文件夹证据，不冒充新的真实FDTD或8许可并行验证。

验证终态与wheel校验记录在`docs/release_3.0.1_validation.json`，原3.0.0原生验证证据保持不变。
